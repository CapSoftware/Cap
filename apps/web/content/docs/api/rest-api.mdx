The Cap Developer API provides programmatic access to videos created through your developer apps. It is designed for server-to-server integrations, automated workflows, and building custom recording experiences on top of Cap.

There are two APIs:

- **REST API** (`/api/developer/v1`) -- Server-side: create uploads and manage videos and usage, authenticated with secret keys (`csk_`).
- **SDK API** (`/api/developer/sdk/v1`) -- Browser-side: upload a video's file, authenticated with an upload token (`cut_`) that your server creates for that one video.

These keys do not authenticate the Cap CLI. For CLI keys (`cap_cli_`), used with `CAP_API_KEY` in headless environments, see [Set Up Your Agent](/docs/agents/setup#headless-environments-ci-containers-and-remote-sandboxes).

## Authentication

### Getting Your API Keys

API keys are managed in Cap Infra, not the general Settings page.

1. Go to [cap.so/dashboard/infra](https://cap.so/dashboard/infra).
2. Create an app and give it a name and environment (development or production).
3. Two keys are generated for each app:
   - **Secret key** (`csk_...`) -- Must be kept private. Used with the REST API, including to create uploads.
   - **Public key** (`cpk_...`) -- Cannot create or upload videos. Browsers upload with an upload token instead.
4. Store both keys securely. You can generate a new pair on the API keys page, which revokes the previous pair.

### Using Your Keys

Include the appropriate key in the `Authorization` header as a Bearer token:

```
Authorization: Bearer csk_your_secret_key_here
```

The SDK API takes an upload token instead. Your server gets one from [Create Upload](#create-upload) and hands it to the browser:

```
Authorization: Bearer cut_your_upload_token_here
```

An upload token works for one video and for a limited time, so it is safe to send to the browser. A public key on its own cannot start an upload: the SDK API answers `403` with code `public_key_not_allowed`.

Keep your secret key private. Never expose it in client-side code, commit it to version control, or share it publicly.

## OpenAPI

A machine-readable OpenAPI 3.1 description of both APIs is published at [Cap.so/openapi.json](https://cap.so/openapi.json). Import it into an API client, generate a typed SDK, or give it to an agent as tool definitions.

## Base URL

**REST API (secret key):**

```
https://cap.so/api/developer/v1
```

**SDK API (upload token):**

```
https://cap.so/api/developer/sdk/v1
```

If you are self-hosting Cap, replace `Cap.so` with your custom domain.

## Error Handling

All error responses return a JSON object with an `error` string. Authentication, rate-limit, unknown-route, and unexpected errors also include a stable `code`, a `hint` describing what to change, and a link to these docs:

```json
{
  "error": "Invalid secret key",
  "code": "invalid_secret_key",
  "message": "Invalid secret key",
  "hint": "Send Authorization: Bearer csk_... with a secret key from https://cap.so/dashboard/infra.",
  "docs": "https://cap.so/docs/api/rest-api"
}
```

Request bodies that fail validation return `400` with `success: false` and the failing fields.

Standard HTTP status codes are used:

| Status Code | Description |
|-------------|-------------|
| `200` | Success |
| `400` | Bad request -- missing or invalid parameters |
| `401` | Unauthorized -- invalid, missing, or revoked API key |
| `402` | Payment required -- the app is out of credit, its balance does not cover 7 days of storage, or it is below the minimum to start a transcript |
| `403` | Forbidden -- a public key was sent to the SDK API, the origin differs from the upload token's `corsOrigin`, or the body names another video |
| `404` | Not found -- the requested resource does not exist |
| `429` | Too many requests -- more than 60 per minute for this key or upload token; wait for `Retry-After` seconds |
| `500` | Internal server error |

## Pagination

List endpoints support pagination via query parameters:

| Parameter | Type | Default | Max | Description |
|-----------|------|---------|-----|-------------|
| `limit` | integer | 50 | 100 | Number of items to return |
| `offset` | integer | 0 | -- | Number of items to skip |

Video lists do not include pagination metadata. To paginate, increment `offset` by `limit` until the returned array has fewer items than `limit`. Transcript lists also return `pagination.hasMore`.

## REST API Endpoints

All REST API endpoints require a secret key (`csk_`) in the `Authorization` header.

### Create Upload

Create a video and an upload token for it. Call this from your server, then give the token to the browser that uploads the file.

```
POST /api/developer/v1/uploads
```

**Request body (JSON):**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | No | Video name (defaults to "Untitled") |
| `userId` | string | No | Your external user ID for filtering |
| `maxResolutionTier` | string | No | Highest resolution to encode: `1080p` (default), `1440p` or `2160p` |
| `metadata` | object | No | Arbitrary metadata to store with the video |
| `corsOrigin` | string | No | Exact origin of the page that uploads, such as `https://app.example.com` |
| `timeoutSeconds` | integer | No | How long the token works, from `60` to `86400`. Defaults to `3600` |

**Example request:**

```bash
curl -X POST https://cap.so/api/developer/v1/uploads \
  -H "Authorization: Bearer csk_your_secret_key_here" \
  -H "Content-Type: application/json" \
  -d '{"name": "User Recording", "userId": "user_42", "corsOrigin": "https://app.example.com"}'
```

**Example response:**

```json
{
  "data": {
    "id": "abc123def456",
    "videoId": "abc123def456",
    "token": "cut_eyJ2IjoxLCJhcHAiOiIuLi4ifQ.Jm2c...",
    "expiresAt": "2026-03-10T15:30:00.000Z",
    "corsOrigin": "https://app.example.com",
    "status": "uploading",
    "uploadUrl": "https://cap.so/api/developer/sdk/v1/upload/multipart",
    "playbackId": "Zk3vQ9s2Lm8Rt1Xy7Bc4Df6G",
    "shareUrl": "https://cap.so/dev/Zk3vQ9s2Lm8Rt1Xy7Bc4Df6G",
    "embedUrl": "https://cap.so/dev/Zk3vQ9s2Lm8Rt1Xy7Bc4Df6G/embed"
  }
}
```

Each video takes one upload, so `id` equals `videoId`. `shareUrl` and `embedUrl` are a hosted player for the video. See [Share and Embed](#share-and-embed).

The token is the only credential the [SDK API](#sdk-api-endpoints) accepts, and it is returned once:

- It uploads this video and no other.
- It works until `expiresAt`. The upload has to complete by then, so raise `timeoutSeconds` for large files on slow connections.
- It stops working when the upload completes or the video is deleted.

`corsOrigin` is a convenience for browser uploads. When it is set, the SDK API refuses a request whose `Origin` header is anything else. A script can send any `Origin` it likes, so the token is what protects the upload, not the origin. Leave `corsOrigin` out to upload from a server or a native app.

Creating an upload is free. It returns `402` if the app is out of credit or its balance does not cover 7 days of storage for what it already stores. The `402` body says how much is needed:

```json
{
  "error": "Insufficient credits",
  "code": "insufficient_credits",
  "message": "Uploading needs $0.20 of credit, enough for 7 days of storage for everything this app stores. The balance is $0.05, so add at least $0.15.",
  "standing": "active",
  "pausesAt": null,
  "balanceMicroCredits": 5000,
  "requiredMicroCredits": 19834,
  "shortfallMicroCredits": 14834
}
```

`code` is `insufficient_credits`, `out_of_credit` (the app is in `grace` or `paused`) or `no_account`.

Check whether a video can be played yet.

```
GET /api/developer/v1/videos/:id/status
```

**Path parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | string | The video ID |

**Example request:**

```bash
curl https://cap.so/api/developer/v1/videos/abc123def456/status \
  -H "Authorization: Bearer csk_your_secret_key_here"
```

**Example response:**

```json
{
  "data": {
    "id": "abc123def456",
    "duration": 124.5,
    "width": 1920,
    "height": 1080,
    "transcriptionStatus": "COMPLETE",
    "ready": true,
    "status": "ready",
    "errorReason": null,
    "playbackId": "Zk3vQ9s2Lm8Rt1Xy7Bc4Df6G",
    "renditions": [
      { "name": "1080p", "width": 1920, "height": 1080, "bitrate": 3565000, "bytes": 55480000, "codecs": "avc1.640028,mp4a.40.2" }
    ],
    "hlsUrl": "https://cap.so/api/developer/playback/Zk3vQ9s2Lm8Rt1Xy7Bc4Df6G/master.m3u8",
    "mp4Url": "https://cap.so/api/developer/playback/Zk3vQ9s2Lm8Rt1Xy7Bc4Df6G/video.mp4",
    "posterUrl": "https://cap.so/api/developer/playback/Zk3vQ9s2Lm8Rt1Xy7Bc4Df6G/poster.jpg"
  }
}
```

The `status` field moves from `uploading` to `processing` when the upload completes, then to `ready` or `errored`. `ready` is `true` when `status` is `ready`. When `status` is `errored`, `errorReason` says why.

A video is `ready` as soon as its first output can be played, so playback can start while the rest is still encoding. The playback URLs are `null` until then. `hlsUrl` is an adaptive HLS master playlist, `mp4Url` is a progressive MP4 and `posterUrl` is a poster image. They need no API key, can be loaded from any origin and stop working when the video is deleted.

On a ready video, one of `hlsUrl` and `mp4Url` can still be `null` while that output finishes encoding. It is filled in later without the video leaving `ready`, and `renditions` is filled in together with `hlsUrl`. Play whichever URL is present.

The `transcriptionStatus` field can be one of: `PROCESSING`, `COMPLETE`, `ERROR`, `SKIPPED`, or `NO_AUDIO`.

### Delete Video

Delete a video. It is excluded from every query straight away, and its playback URLs stop answering new viewers within about a minute. Its files (the upload and every encoded output) are removed within about five minutes, and links that were already handed out stop working within about ten minutes of the delete. If the video was still being encoded when it was deleted, anything the encoder writes afterwards is removed within four hours.

```
DELETE /api/developer/v1/videos/:id
```

**Path parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | string | The video ID |

**Example request:**

```bash
curl -X DELETE https://cap.so/api/developer/v1/videos/abc123def456 \
  -H "Authorization: Bearer csk_your_secret_key_here"
```

**Example response:**

```json
{
  "success": true
}
```

### Transcripts

Send an audio or video file and get text back. Transcription costs $0.10 per audio hour, billed by the second from the app's credit balance.

A transcript moves through these statuses: `uploading` (waiting for its file), `queued`, `processing`, then `complete` or `error`. Poll [Get Transcript](#get-transcript) every few seconds until the status is `complete` or `error`. Each key allows 60 requests per minute.

Creating or starting a transcript can be refused. The response carries a `code` and a `message`:

| Status | Code | Meaning |
|--------|------|---------|
| `402` | `out_of_credit` | The app is in `grace` or `paused` because a daily storage charge could not be paid. The message says how much to add |
| `402` | `insufficient_credits` | The available balance is under $0.01. The message says how much to add |
| `409` | `idempotency_conflict` | The `Idempotency-Key` was already used for a different request, or for a transcript that was deleted |
| `409` | `upload_not_found` | The file has not been uploaded yet |
| `503` | `speech_unavailable` | Transcription is temporarily unavailable. Retry later |

#### Transcribe a URL

```
POST /api/developer/v1/transcripts
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `url` | string | Yes | Public `http` or `https` URL of an audio or video file |
| `name` | string | No | Display name (defaults to the file name) |
| `language` | string | No | Two-letter code such as `en`, or `auto` (default) |
| `userId` | string | No | Your own user identifier, used to filter lists |
| `metadata` | object | No | Your own JSON object, under 8KB |

The URL must use the default port, must not contain credentials and must resolve to a public address. Redirects are followed up to five times and each hop is checked the same way. Files can be up to 2 GB, or 400 MB when the server does not send a `Content-Length`. Audio can be up to 4 hours long.

```bash
curl -X POST https://cap.so/api/developer/v1/transcripts \
  -H "Authorization: Bearer csk_your_secret_key_here" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: standup-2026-11-11" \
  -d '{"url": "https://example.com/standup.mp3"}'
```

```json
{
  "data": {
    "id": "8kq2m4x7n1p3v5w",
    "status": "queued",
    "name": "standup",
    "source": { "type": "url", "url": "https://example.com/standup.mp3" },
    "durationSeconds": null,
    "language": null,
    "wordCount": null,
    "costMicroCredits": 0,
    "costDollars": 0,
    "error": null,
    "userId": null,
    "metadata": null,
    "createdAt": "2026-11-11T10:30:00.000Z",
    "updatedAt": "2026-11-11T10:30:00.000Z",
    "completedAt": null
  }
}
```

Send an `Idempotency-Key` header (8 to 128 characters) so a retried request returns the same transcript instead of creating and billing a second one.

#### Transcribe a file

Uploading takes three calls: create the transcript, PUT the file, then start it.

```
POST /api/developer/v1/transcripts/uploads
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `contentLength` | integer | Yes | Exact file size in bytes, up to 2 GB |
| `fileName` | string | No | Original file name |
| `name`, `language`, `userId`, `metadata` | | No | Same as above |

The response is the transcript in the `uploading` status plus an `upload` object with a signed URL that is valid for one hour. Audio can be up to 4 hours long.

```bash
FILE=standup.m4a
SIZE=$(wc -c < "$FILE" | tr -d ' ')

CREATED=$(curl -s -X POST https://cap.so/api/developer/v1/transcripts/uploads \
  -H "Authorization: Bearer csk_your_secret_key_here" \
  -H "Content-Type: application/json" \
  -d "{\"fileName\": \"$FILE\", \"contentLength\": $SIZE}")

ID=$(echo "$CREATED" | jq -r .data.id)

curl -X PUT -T "$FILE" "$(echo "$CREATED" | jq -r .data.upload.url)"

curl -X POST "https://cap.so/api/developer/v1/transcripts/$ID/start" \
  -H "Authorization: Bearer csk_your_secret_key_here"
```

A single signed PUT is used instead of a multipart upload because it is one request any HTTP client can make. The upload must be exactly `contentLength` bytes. Starting a transcript twice is safe: the second call returns the transcript unchanged.

```json
{
  "data": {
    "id": "8kq2m4x7n1p3v5w",
    "status": "complete",
    "name": "standup",
    "source": { "type": "upload", "url": null },
    "durationSeconds": 754.2,
    "language": "en",
    "wordCount": 1893,
    "text": "Morning everyone. Quick update from my side...",
    "costMicroCredits": 2097,
    "costDollars": 0.02097,
    "error": null,
    "userId": null,
    "metadata": null,
    "createdAt": "2026-11-11T10:30:00.000Z",
    "updatedAt": "2026-11-11T10:30:21.000Z",

  }

```

A failed transcript has the status `error` and an `error` object with one of these codes:

| Code | Meaning |
|------|---------|
| `insufficient_credits` | The available balance could not cover the hold for the transcript, or the transcript itself. The message says how much was needed |
| `source_unreachable` | The URL could not be downloaded |
| `source_blocked` | The URL, or a redirect from it, did not point to a public address |
| `source_too_large` | The file is larger than 2 GB |

```
DELETE /api/developer/v1/transcripts/:id
```

#### Transcript billing

- The price is $0.10 per audio hour, which is 10,000 micro-credits. Cap measures the audio length itself and bills it to the nearest second, with a minimum of one second. A length sent by the client is never used.
- Creating or starting a transcript needs an app in good standing and an available balance of at least 1,000 micro-credits ($0.01). Otherwise the API answers `402`, with `code` set to `out_of_credit` when the app is in `grace` or `paused` and `insufficient_credits` when the balance is under the minimum. The `message` says how much to add.
- Credits are taken once, when the transcript completes. Failed and deleted transcripts cost nothing, and a transcript that is retried internally is never charged twice.
- Starting holds up to the cost of four hours ($0.40) until the audio is measured, then the hold drops to the real cost. The hold is placed before the file is downloaded or processed and nothing is charged for it. It is sized from the file: a file under 180 KB holds $0.01, a file of 7.2 MB or more holds the full $0.40, and a URL that does not report its size holds $0.40. The available balance is your balance minus those holds.
- If the available balance cannot cover the hold, the transcript ends with `insufficient_credits` before the file is downloaded or processed, and the error message says how much was needed. When other running transcripts hold the credit, it waits for them for up to 15 minutes first, so a batch started together runs through as holds are released.
- Credit held for a running transcript is left alone by the daily storage charge and is not counted when uploads are admitted. If the balance still cannot pay for a transcript in full when it finishes, the transcript ends with `insufficient_credits`, its text is discarded and nothing is charged. Top up and submit it again.
- Cap deletes the source file once the transcript finishes. The text and timings are kept until you delete the transcript.

### Get Usage

Retrieve your app's credit balance, video totals, standing, what it needs to take an upload and what storage costs per day.

```
GET /api/developer/v1/usage
```

**Example request:**

```bash
curl https://cap.so/api/developer/v1/usage \
  -H "Authorization: Bearer csk_your_secret_key_here"
```

**Example response:**

```json
{
  "data": {
    "balanceMicroCredits": 500000,
    "balanceDollars": "5.00",
    "totalVideos": 23,
    "totalDurationMinutes": 87.5,
    "standing": { "state": "active", "pausesAt": null },
    "upload": {
      "allowed": true,
      "reason": null,
      "requiredMicroCredits": 1736,
      "shortfallMicroCredits": 0,
      "message": null
    },
    "storage": {
      "minutesByTier": { "1080p": 87.5, "1440p": 0, "2160p": 0 },
      "dailyMicroCredits": 247,
      "monthlyMicroCredits": 7438
    }
  }
}
```

Credits are tracked in micro-credits (1 dollar = 100,000 micro-credits).

**What is billed.** Uploading and encoding are free. Stored video is charged once a day, for each video by its length and resolution tier, with a month counted as 30 days. The tier comes from the pixel count of the video.

| Tier | Pixels | Storage per 1,000 minutes per month |
|------|--------|-------------------------------------|
| `1080p` | up to 2,073,600 | $0.85 |
| `1440p` | up to 4,194,304 | $1.45 |
| `2160p` | above 4,194,304 | $2.80 |

**Uploading.** `upload.allowed` is true when the app is in good standing and its balance covers 7 days of storage for everything it stores. `upload.requiredMicroCredits` is that amount and `upload.shortfallMicroCredits` is how much to add.

**Standing.** `standing.state` is one of:

| State | Meaning |
|-------|---------|
| `active` | In good standing. |
| `grace` | A daily storage charge was more than the balance. The balance was taken to zero, uploads are blocked, and playback continues until `pausesAt`, 7 days after the app first fell short. |
| `paused` | Playback is paused until credits are added. Videos stay stored. |

Adding credits that cover one day of storage returns the app to `active` at once. Days it could not pay for are not charged afterwards.

## SDK API Endpoints

The SDK API uploads a video's file from a browser or app. Every endpoint takes the upload token from [Create Upload](#create-upload) in the `Authorization` header. The token already names the video, so `videoId` in a request body is optional, and a `videoId` that is not the token's returns `403` with code `video_mismatch`.

| Status | `code` | Meaning |
|--------|--------|---------|
| `401` | `invalid_upload_token` | The token is missing, malformed or altered |
| `401` | `upload_token_expired` | The token is past `expiresAt`. Create a new upload |
| `403` | `public_key_not_allowed` | A public key was sent. Public keys cannot create or upload videos |
| `403` | `origin_not_allowed` | The token has a `corsOrigin` and the `Origin` header is different |
| `403` | `video_mismatch` | The body names a video other than the token's |
| `404` | `video_not_found` | The token's video was deleted |

### Multipart Upload

After creating an upload, use multipart upload to send the video file. This is a multi-step process.

#### Initiate Upload

```
POST /api/developer/sdk/v1/upload/multipart/initiate
```

**Request body (JSON):**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `videoId` | string | No | The token's video ID |
| `contentType` | string | No | MIME type (defaults to "video/mp4") |

**Example response:**

```json
{
  "uploadId": "multipart-upload-id"
}
```

#### Get Presigned Part URL

Get a presigned URL to upload a single part.

```
POST /api/developer/sdk/v1/upload/multipart/presign-part
```

**Request body (JSON):**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `videoId` | string | No | The token's video ID |
| `uploadId` | string | Yes | The upload ID from the initiate step |
| `partNumber` | number | Yes | Part number (starting from 1) |

**Example response:**

```json
{
  "presignedUrl": "https://s3.amazonaws.com/..."
}
```

Upload the part data by sending a `PUT` request to the returned `presignedUrl`. Save the `ETag` header from the response for the completion step.

#### Complete Upload

Finalize the upload after all parts have been uploaded.

```
POST /api/developer/sdk/v1/upload/multipart/complete
```

**Request body (JSON):**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `videoId` | string | No | The token's video ID |
| `uploadId` | string | Yes | The upload ID |
| `parts` | array | Yes | Array of uploaded parts |
| `parts[].partNumber` | number | Yes | The part number |
| `parts[].etag` | string | Yes | The ETag returned when the part was uploaded |
| `parts[].size` | number | Yes | The size of the part in bytes |
| `durationInSecs` | number | Yes | Positive video duration in seconds (validated and used for billing) |
| `width` | number | No | Video width in pixels |
| `height` | number | No | Video height in pixels |
| `fps` | number | No | Video frame rate |

**Example response:**

```json
{
  "success": true
}
```

Completing an upload charges nothing. The video's stored `duration` is the greater of the submitted duration and a minimum based on the part sizes reported by storage, bounded by what the uploaded bytes could hold and capped at four hours. Storage for the video is billed daily from then on, by its length and resolution tier. Each listed part must already be uploaded with the ETag you send, otherwise the request returns `400`.

The balance must cover 7 days of storage for everything the app stores including this video. If it does not, complete returns `402` with the same body as [Create Upload](#create-upload), and the upload stays open so the same request succeeds after a top-up. The one exception is when several uploads finish at once and together exceed the balance: the `402` then carries `"fileRemoved": true`, the file that was just assembled has been removed, and it must be uploaded again once credit is added.

Each video accepts one completed upload, and its token is used up with it. Once the upload completes, initiate, presign-part and abort return `409` with code `upload_already_completed`, and repeating complete returns `{ "success": true }` without doing anything.

Complete can itself return `409` with a `code`:

| `code` | Meaning | What to do |
|--------|---------|------------|
| `completion_in_progress` | Another request is completing this upload right now, for example your own earlier request whose response was lost. | Wait a few seconds and send the same complete request again. Do not abort the upload or delete the video. |
| `upload_removed` | The upload sat unrecorded for more than a day and was removed. | Create a new upload and send the file again. |

Abort also returns `409` with `completion_in_progress` while a completion holds the video. Uploads for deleted videos return `404`. To upload a new file, create a new upload.

#### Abort Upload

Cancel an in-progress multipart upload.

```
POST /api/developer/sdk/v1/upload/multipart/abort
```

**Request body (JSON):**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `videoId` | string | No | The token's video ID |
| `uploadId` | string | Yes | The upload ID to abort |

**Example response:**

```json
{
  "success": true
}
```

## Share and Embed

Every video has a hosted player, returned as `shareUrl` and `embedUrl` when you create an upload and when you get or list a video. Both are built from the video's `playbackId`, need no API key or sign-in, set no cookies and are kept out of search engines.

- `shareUrl` is a page with the player and the video's name. Send it to a viewer as a link.
- `embedUrl` is the player alone, filling whatever frame you give it. Any site can load it in an iframe:

```html
<iframe
  src="https://cap.so/dev/Zk3vQ9s2Lm8Rt1Xy7Bc4Df6G/embed"
  title="Product Demo"
  style="width: 100%; aspect-ratio: 16 / 9; border: 0"
  allow="fullscreen; picture-in-picture"
  allowfullscreen
></iframe>
```

Set the iframe's `aspect-ratio` from the video's `width` and `height`. The links work as soon as the video is created: until it is `ready` the page says the video is processing and switches to the player by itself, and if processing failed it shows `errorReason`. A deleted video returns `404`, and a video in an app whose playback is paused says so.

## SDKs

Cap provides official SDK packages to simplify integration:

- **`@cap/sdk-recorder`** -- Recording SDK for capturing video in web applications. Includes React bindings. Give it a `createUpload` function that asks your server for an upload, and it uploads the recording with the token.
- **`@cap/sdk-embed`** -- Embedding SDK for displaying Cap videos. Available for React and vanilla JavaScript.

## Best Practices

- **Use secret keys server-side only.** The `csk_` key should never appear in client-side code. Create each upload on your server and send only its `cut_` upload token to the browser.
- **Poll video status after upload.** After completing a multipart upload, poll `GET /videos/:id/status` until `ready` is `true`, then play `hlsUrl` when it is present and `mp4Url` otherwise.
- **Store your keys securely.** Use environment variables or a secrets manager.
- **Check who is uploading before you create an upload.** Your server decides who gets a token, so authenticate the user first and set `userId` to tie the video to them.
- **Monitor your credit balance.** Use the usage endpoint to track the balance, `standing` and `upload.allowed`, and top up from your app's Billing page in Cap Infra. Auto top-up on that page adds credits from a saved card when the balance runs low.
- **Paginate large result sets.** Use `limit` and `offset` to retrieve videos in batches. When the returned array length is less than `limit`, you have reached the end.
