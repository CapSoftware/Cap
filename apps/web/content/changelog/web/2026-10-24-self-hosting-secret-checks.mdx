---
title: Required Secrets for Self-Hosted Upgrades
publishedAt: "2026-10-24"
---

Self-hosted Cap now refuses to start with missing secrets or the public example values shipped in older Compose files. Generate unique `NEXTAUTH_SECRET`, `DATABASE_ENCRYPTION_KEY` and `MEDIA_SERVER_WEBHOOK_SECRET` values before a new installation. Use the same webhook secret on cap-web and the media server. Coolify already generates unique secrets per deployment.

## Upgrading an Existing Installation

Back up MySQL and read the [upgrade instructions](/docs/self-hosting#upgrading-from-an-older-release) before changing secrets. Update the repository and any copied Compose template, then pull images and rebuild the media server from the updated source. Adding values to `.env` does not replace secrets hardcoded in an older template.

Changing `DATABASE_ENCRYPTION_KEY` makes existing encrypted storage settings, developer app keys and integration credentials unreadable. To upgrade before migrating that data, retain the exact existing valid encryption key and explicitly set `CAP_ALLOW_INSECURE_SECRETS=true` on cap-web. This temporary override logs a warning on every affected startup and keeps missing-secret and key-format checks enforced. Rotate authentication and webhook secrets, plan the encrypted-data migration, and remove the override after rotating the encryption key.
