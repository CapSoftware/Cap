Q3 Capture Pipeline Review

Prepared by Maya Lindqvist · Desktop & Media team · 📅 Oct 6, 2026

Summary

This quarter we shipped the new capture pipeline to every desktop user. Recordings now start in under a second on most machines, the editor opens files twice as fast, and the number of failed uploads dropped by more than half. The remaining work is mostly about long recordings on older laptops, where memory use still grows too quickly after the first twenty minutes.

Highlights

Encoder

  • Hardware encoding is now the default on Apple Silicon and on recent Intel and AMD GPUs.
  • Screen content mode cuts the size of text-heavy recordings by about 30% at the same quality.
  • Keyframes are placed on scene changes, so seeking in the web player feels instant.

Capture and upload

Segments are uploaded while the recording is still running, which means a ten minute video is usually ready to share a few seconds after the user clicks stop. We also added a resumable upload path for flaky connections; it has already recovered more than 4,000 recordings that would have failed before.

Risks

Memory growth on long recordings is the biggest open issue. We see it mostly on machines with 8 GB of RAM when the camera overlay is enabled, and it can lead to dropped frames after about half an hour. A fix for the frame pool is in review and should land in the next release.

Next steps

For Q4 we want to finish the work on long recordings and start testing the new encoder with real customer content.
